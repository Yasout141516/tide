# Tide M7: Ship (core) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Tide releasable as v1.0.0. That means a real app icon, an About box, the FFmpeg source attached to every release, a release dry run, a README for Yasin, a polished first-launch screen, and the spec's acceptance list checked against evidence.

**Architecture:** This milestone adds almost no new product code.
- **Icon:** generated from one SVG master by a script.
- **About box:** comes from the main process. macOS uses `app.setAboutPanelOptions`; Windows gets a Help menu item that opens a native message box.
- **Release workflow:** gains a FFmpeg source step and a manual dry-run trigger.
- **Docs:** the README and an acceptance checklist.

**Tech Stack:** Electron 45, electron-builder, electron-vite, React 19, TS, vitest, Playwright, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-16-tide-design.md`. The relevant sections are §5.1 screen 2 (First launch), §7 M7, §8 (acceptance criteria), §10 (supporting deliverables 1–2) and §12 ("Still open": GPL ffmpeg). Mockup: `docs/design/screens-sky-sea.html`, screen 2.

**Scope confirmed with Yasin (2026-11-27):**
- In scope: the core ship items. FFmpeg source is attached to every GitHub Release. The first-launch screen is polished, not redesigned. The icon is built from the existing sun-and-wave wordmark.
- Out of scope for this plan:
  - Her guides ("Opening Tide the first time", "Getting audio onto your iPhone"). These need Mac screenshots at hand-off.
  - Windows "Open With".
  - The parked fixes (startup sweep of `.part` and temp files after a crash; macOS timing-test limits).
  - Tagging and publishing `v1.0.0`. Yasin does that himself, and is asked each time.
  - The hand-off session.

## Global Constraints

- Machine quirks:
  - Run `unset ELECTRON_RUN_AS_NODE` before npm, vitest, electron or playwright.
  - Work from `cd /d/pdf-narrator && …`.
  - Installs use `NODE_EXTRA_CA_CERTS=D:/pdf-narrator/.superpowers/roots.pem` and **exact pins**.
- No network at runtime. The `TIDE_OFFLINE_GUARD=1` e2e must stay green.
- The Mac build is arm64 only and ad-hoc signed (`identity: '-'`). Never add a real signing identity.
- Never push to `main`, push a tag, or publish a release without asking Yasin each time. Feature-branch pushes are allowed.
- Nothing from `local-fixtures/` may reach code, tests, logs or commits.
- No Nintendo or Sanrio IP. Tokens only in renderer UI. Plain accessible names. Every click target ≥ 36 px tall.
- Commit after each task with a Conventional Commit subject.

## Review Focus

1. **Icon at small sizes.** The 16 px and 32 px renders (Windows taskbar, Finder list view) must still read as sun and wave, not a blur. Test: the script also writes a 16 px and 32 px preview, and the controller looks at them (Task 1).
2. **A release built without the source tarball.** The workflow must fail if the FFmpeg download or checksum fails, so a release never ships without the source (Task 3).
3. **About on Windows.** The Windows menu bar is hidden until Alt, so "About Tide" must also be reachable from the Help menu, not only from a macOS-style app menu (Task 2).
4. **README accuracy.** Every command in the README must actually run on a fresh clone in the stated order. The implementer runs each one and records the output (Task 4).
5. **Licences offline.** The About box's "View licences" must open the bundled NOTICE without any network (Task 2).

### Task 3: FFmpeg source on every release, plus a dry run

**Files:**
- Modify: `.github/workflows/release.yml`, `NOTICE.md` (FFmpeg section)
- Create: `scripts/ffmpeg-source.json` (pinned URL and SHA-256 for `ffmpeg-6.1.1.tar.xz`, plus the ffmpeg-static 5.3.0 build-info links already in NOTICE)

**Interfaces:**
- `release.yml` triggers:
  - `push: tags: ['v*']` (unchanged).
  - `workflow_dispatch` with input `dry_run` (boolean, default `true`).
- New job steps (Linux job `ffmpeg-source`, independent of the OS matrix):
  1. Download the tarball from the pinned URL.
  2. Verify the SHA-256 from `scripts/ffmpeg-source.json`. A mismatch fails the job.
  3. Write `FFMPEG-SOURCE.md`. It states the FFmpeg version, the ffmpeg-static version and release tag, and links to the builders' build scripts already listed in NOTICE.md.
  4. On a tag: `gh release upload "$GITHUB_REF_NAME" ffmpeg-6.1.1.tar.xz FFMPEG-SOURCE.md --clobber`. This runs after the matrix jobs have created the draft (`needs:` the matrix).
  5. On a dry run: upload the files as a workflow artifact instead.
- Dry run (`workflow_dispatch`):
  - The matrix jobs build with `npx electron-builder --publish never`.
  - They upload `release/*.dmg` and `release/*.exe` as workflow artifacts.
  - Nothing is published and no tag is needed.
- NOTICE.md FFmpeg section: add "The exact FFmpeg source for the bundled binary is attached to every Tide release on GitHub (`ffmpeg-6.1.1.tar.xz`)." Keep the existing links.

- [ ] **Step 1: Pin the checksum.** Download `https://ffmpeg.org/releases/ffmpeg-6.1.1.tar.xz` once and record its SHA-256 in `scripts/ffmpeg-source.json`. Cross-check against the published `.asc` or checksum if one is available, and say what you checked.
- [ ] **Step 2: Implement** the workflow changes. Keep the existing tag path byte-for-byte the same apart from the new job.
- [ ] **Step 3: Validate the YAML locally.** If `npx --yes @action-validator/cli` or `actionlint` can run offline, use it. Otherwise parse the file with the `yaml` package and assert the triggers, jobs and `needs`. Record the command and its output.
- [ ] **Step 4: Commit** `ci: attach FFmpeg source to releases and add a release dry run`. Push the branch.
- [ ] **Step 5: Dry run.** Run `gh workflow run release.yml --ref feat/m7-ship -f dry_run=true`, then watch it with `gh run watch`.
  - GitHub may refuse because the default branch's `release.yml` has no `workflow_dispatch` trigger yet. If so, report BLOCKED with the exact error. The controller will then ask Yasin whether to allow a throw-away `v1.0.0-rc.1` tag, which only creates a draft release that can be deleted.
  - Report the artifact names and sizes and the source-job result.
